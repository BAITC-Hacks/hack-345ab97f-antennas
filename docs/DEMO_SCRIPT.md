# Сценарий показа

Перед началом: `cd frontend && npm run dev`, откройте **http://localhost:5173/call**. В шапке должен быть **DEMO**, на странице — **Demo data**. Для live нужен работающий backend и `VITE_DEMO_MODE=false`; текущий live контракт предварительный.

1. **Два намерения.** Нажмите «Два намерения · RU». Последовательно появятся состояния прослушивания, распознавания, маршрутизации и ответа. Итог: `payment_not_confirmed`, confidence 86%, адрес в очереди.
2. **Трассировка.** Нажмите «Открыть трассировку». Итог: waterfall с выделенным Router, причина решения, `refund_request` как альтернатива, raw JSON в раскрываемом блоке.
3. **Казахский.** Вернитесь к звонку, нажмите «Қазақша · KK». Итог: метка KK и ответ на казахском.
4. **Mixed.** Нажмите «Mixed». Итог: метка MIXED, обнаружены вопросы оплаты и адреса.
5. **Новый сценарий.** В `/catalog` нажмите «Новый сценарий», заполните ID, название и описание, сохраните. Итог: строка сразу в списке, после обновления страницы сохраняется.
6. **Супервизор.** В `/supervisor` отфильтруйте язык и решение, откройте трассировку выбранного диалога. Итог: переход на верную запись.
7. **Запасной путь.** При отказе микрофона отправьте текст в поле. Разрешение на микрофон нужно только для локального индикатора записи; демо не зависит от аудиопайплайна.

Не называйте подготовленные 1195 мс измеренным p95. Показатели качества в супервизоре ждут реального eval.
