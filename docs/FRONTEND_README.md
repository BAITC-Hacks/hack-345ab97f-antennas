# Tyńda Voice Router

Voice Router принимает реплику клиента, определяет язык, выбирает сценарий и показывает оператору причину решения и задержку каждого этапа. Интерфейс работает без backend в демонстрационном режиме. Демо-решения и задержки являются подготовленными примерами, а показатели качества ожидают настоящего eval.

## Скриншот

Добавьте финальный снимок экрана звонка в `docs/screenshots/call.png` перед публикацией. Подходящий кадр: реплика с двумя намерениями, выбранный сценарий и кнопка трассировки.

## Быстрый запуск

Требуется Node.js 20.19+ или 22.12+ и npm.

```bash
cd frontend
npm install
copy .env.example .env
npm run dev
```

На macOS/Linux вместо `copy` используйте `cp`. Адрес: **http://localhost:5173/call**.

### Demo mode

`VITE_DEMO_MODE=true` — режим по умолчанию даже без `.env`. Каталог и новые диалоги сохраняются в `localStorage`. В интерфейсе виден бейдж **Demo data**. Можно нажать «Два намерения · RU» или отправить собственный текст. Демо последовательно показывает состояния `listening → recognizing → thinking → speaking → completed`.

### Live mode

В `frontend/.env` задайте:

```dotenv
VITE_DEMO_MODE=false
VITE_API_URL=http://localhost:8000
VITE_WS_URL=ws://localhost:8000/ws
```

Перезапустите Vite после изменения переменных. Live адаптер находится в `frontend/src/api/realApi.ts`. В доступном workspace **нет backend или его схемы**, поэтому пути и события там являются предварительным контрактом; их необходимо согласовать до подключения. Ошибки REST и WebSocket показываются на экране звонка. При разрыве есть повторное подключение.

## Экраны

| Путь | Назначение |
| --- | --- |
| `/call` | Начать/завершить звонок, разрешить микрофон, отправить текстовую реплику, увидеть транскрипт, маршрут, дополнительные намерения и ответ. |
| `/trace` | Посмотреть решение, альтернативы, raw JSON и waterfall из шести этапов. |
| `/supervisor` | Последние диалоги, фильтры, handoff и распределение задержки последней трассировки. Метрики качества показаны как «—» до реального eval. |
| `/catalog` | Поиск, создание и изменение сценариев; в demo данные переживают перезагрузку. |

## Архитектура frontend

`src/types.ts` задаёт общие модели `Transcript`, `RouteDecision`, `TraceTimings`, `Scenario`, `Dialog` и интерфейс `VoiceRouterApi`. `src/api/index.ts` выбирает `mockApi` либо `realApi` по `VITE_DEMO_MODE`; компоненты работают с единым интерфейсом. Mock каталог находится только во frontend и не выдаётся за backend.

Микрофон запрашивает разрешение и показывает состояние локальной записи. Формат передачи аудио backend не определён, поэтому отправка звука не реализована: для обработки реплики используется обязательный текстовый ввод. Если backend вернёт URL TTS, браузер попытается его воспроизвести; при ошибке текст ответа остаётся доступным.

Предварительные live endpoints: `GET /scenarios`, `PUT /scenarios/:id`, `GET /dialogs`, `GET /dialogs/:id`, `POST /calls`, `POST /calls/:id/turns`, `POST /calls/:id/end`, WebSocket `/ws?callId=…`. Они указаны для интеграции, **не подтверждены backend**.

## Проверка за 5 минут

1. Проверьте бейдж **DEMO** в шапке; откройте `/call`.
2. Нажмите «Два намерения · RU». Дождитесь «Ответ готов». Основной сценарий — `payment_not_confirmed`, следом — `change_delivery_address`.
3. Откройте трассировку: Router выделен, total равен 1195 мс для подготовленного примера, есть альтернативный `refund_request`.
4. Вернитесь на звонок и нажмите «Қазақша · KK», затем «Mixed». Проверьте языковые метки и текстовый fallback.
5. В `/catalog` создайте новый сценарий с уникальным ID, сохраните, обновите страницу и найдите его поиском.
6. В `/supervisor` отфильтруйте записи по языку/решению и откройте трассировку строки.

## Почему LLM router

Демо-реплика содержит две задачи сразу: проверить списанную оплату и затем изменить адрес. Маршрутизатор возвращает основной сценарий, очередь дополнительных намерений, альтернативу и текстовую причину. Это модель решения над контекстом и границами сценариев, а не одиночная метка intent. **В демо режимe решение имитируется локальными правилами; реальный LLM подключается через backend.**

## Известные ограничения

- Демо использует подготовленные задержки, а не замер сетевого вызова. Их нельзя трактовать как p50/p95 или accuracy.
- Контракт REST/WebSocket и аудиоформат должны быть согласованы с командой backend. Live адаптер пока предварительный.
- Голос не отправляется в backend без согласованного аудиопротокола; текстовый ввод работает.
- Демо-каталог хранится только в браузере пользователя.
- Финальный скриншот и реальный eval следует добавить перед публичной защитой.
