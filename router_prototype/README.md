# Router prototype — учебный прототип LLM-роутера

Прототип роутера для Voice Router (HackAlem AI × Halyk) на 10 выдуманных сценариях страховой.
Цель — отработать промпт, JSON-схему и замеры **до** хакатона. В день хакатона меняем
`catalog.json` на `scenarios.json` из стартового кита.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # и впиши ключ, модель и адрес провайдера

python router.py --show-prompt "Хочу продлить страховку"   # посмотреть промпт (ключ не нужен)
python router.py "Хочу продлить страховку"                 # одна фраза через LLM
python router.py "Астана, Туран 55" --state '{"active_scenario": "change_delivery_address", "last_assistant_message": "Назовите новый адрес"}'
python run_eval.py                                         # прогон всего тестового набора
```

## Что в папке

| Файл | Что делает |
| --- | --- |
| `catalog.json` | 10 сценариев: назначение, границы с соседями, параметры, примеры на ru и kk |
| `tests.json` | 24 тестовые фразы: simple, boundary, mixed, multi, topic_switch, clarify, handoff |
| `schema.py` | Формат ответа: JSON Schema для LLM + Pydantic-модель для проверки |
| `prompt.py` | Сборка промпта: правила + каталог (не меняются) и состояние диалога + фраза (меняются) |
| `router.py` | Вызов LLM, замер времени, разбор и проверка ответа |
| `run_eval.py` | Точность по типам и языкам, p50/p95 задержки, частые путаницы, отчёт в `reports/` |

## Как это работает (простыми словами)

1. `prompt.py` превращает каталог в компактный текст и приклеивает правила на английском.
   Эта часть одинаковая для всех запросов, поэтому провайдер может её закэшировать.
2. К ней добавляется состояние диалога (какой сценарий активен, что робот спросил, какие темы
   отложены) и новая фраза клиента.
3. `router.py` отправляет это в LLM и требует ответ строго по JSON Schema из `schema.py`.
   Поле `scenario_id` — enum из id каталога, выдумать несуществующий сценарий нельзя.
4. Ответ проверяется ещё раз через Pydantic. Сломанный JSON или чужой id → понятная ошибка.
5. `run_eval.py` прогоняет все тестовые фразы и показывает, где роутер ошибается и почему
   (поле `reason` из ответа модели).

## Твои задания (по порядку)

- [ ] **1. Запусти.** Получи ключ одного провайдера, заполни `.env`, запусти `run_eval.py`.
      Запиши точность и p50.
- [ ] **2. Bake-off.** Прогони тот же набор на 2–3 разных моделях (удобно через OpenRouter:
      меняешь только `LLM_MODEL`). Сравни точность, p50 и цену. Отчёты уже лежат в `reports/`.
- [ ] **3. Анализ ошибок.** Для каждой ошибки прочитай `причина модели` и реши, что чинить:
      описание сценария, правило границы или правило в `RULES`. Чинить смысл, а не конкретную фразу.
- [ ] **4. Казахский.** Фразы на казахском писал ИИ — пусть тот, кто лучше всех знает казахский,
      проверит их и добавит ещё 10 своих, живых, как говорят в жизни.
- [ ] **5. Holdout.** Раздели тесты на две части: на первой настраиваешь, вторую не трогаешь до
      финального замера. Иначе цифра точности будет завышенной.
- [ ] **6. Следующий урок: early commit** — потоковый ответ (`stream=True`) и запуск сценария,
      как только пришёл `scenario_id`. Разберём вместе.
- [ ] **7. Потом: уверенность через logprobs** вместо цифры, которую пишет сама модель.

## Известные ограничения прототипа

- `confidence` пока пишет сама модель — она склонна завышать. Логпробы — задание 7.
- Роутер ждёт полный ответ модели; early commit ещё не сделан (задание 6).
- Reasoning-модели могут не принимать `temperature=0` и `max_tokens` — для роутера они всё равно
  слишком медленные, бери быстрые.
