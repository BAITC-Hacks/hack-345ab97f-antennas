# OpenAI API: ключ только на сервере

Эта инструкция относится к изолированному frontend smoke-test на 8787. Для полноценного Gateway на 8000 используйте [.env и инструкцию backend](../voice-router-backend/README.md). Два сервера читают разные файлы .env; автоматически ключи между папками не копируются.

Ранее опубликованный в переписке ключ следует отозвать. Для проекта создайте новый ключ самостоятельно; не присылайте его в чат и не помещайте в HTML/JS.

## Настройка

1. Скопируйте .env.example в .env в папке voice-router-frontend.
2. Впишите новый OPENAI_API_KEY только в .env. OPENAI_MODEL задаёт доступную вашему проекту модель; значение по умолчанию — gpt-5-mini.
3. Запустите node server.mjs. После изменения .env нужен перезапуск.
4. Откройте http://127.0.0.1:8787/api/health. openaiConfigured сообщает лишь о наличии настройки, а не о валидности ключа.
5. Без параметра gateway отправьте текст через экран «Звонок». Это проверка соединения, не выбор сценария.

.env загружается рядом с server.mjs независимо от рабочей папки. Значения окружения имеют приоритет. .gitignore исключает секреты. HTTP-сервер отдаёт только пять публичных файлов; .env, код сервера и документы недоступны через него.

```powershell
Invoke-RestMethod http://127.0.0.1:8787/api/route -Method Post -ContentType 'application/json' -Body '{"text":"Здравствуйте"}'
```

## Обработка ошибок

| Код | Значение |
|---|---|
| not_configured | На сервере нет ключа |
| api_auth | API отклонил ключ или доступ |
| api_limit | Квота/лимит upstream |
| timeout | Ожидание более 30 секунд |
| busy | Уже выполняются два запроса |
| empty_response | Нет завершённого текстового ответа |
| upstream_error | Иная сетевая/API-ошибка |

Клиент не получает исходные сообщения upstream с потенциально чувствительными данными. Тело запроса — до 8 KiB, text — 1–600 символов. Сервер привязан к 127.0.0.1 и проверяет Host/Origin. Это локальный dev proxy без авторизации — не публичный backend.

Responses API вызывается с store: false, но это не обещание отсутствия любой обработки/логирования у провайдера. Используйте синтетические фразы. Текст извлекается из output[].content[] типа output_text, включая сообщения после reasoning-элементов. См. [официальное руководство по генерации текста](https://developers.openai.com/api/docs/guides/text).

Автотесты подменяют API; успешный платный вызов с новым ключом ещё не проверен.
