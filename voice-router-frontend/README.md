# Tyńda · Voice Router frontend

Пакет участника 3: звонок, трассировка, супервизор, редактор каталога и материалы для питча. HTML/CSS/JavaScript + Node.js; без сборки и внешних npm-зависимостей.

## Полный локальный запуск с backend

Теперь рядом есть [voice-router-backend](../voice-router-backend/README.md). Из корня репозитория запустите `node voice-router-backend/src/server.mjs` и откройте http://127.0.0.1:8000. Backend автоматически подключит WebSocket. Инструкция ниже остаётся полезной для изолированного frontend.

При подключении нового backend каталог и история загружаются с сервера, примеры отправляются в Gateway, KPI считаются по сохранённым решениям, а accuracy остаётся пустой без eval. Каталог можно удалять на сервере, очередь операторов открывается в диалоге. TTS проигрывается с управляющими кнопками и пометкой «голос ИИ».

## Запуск

Требуется Node.js 20 или новее. Из корня командного репозитория:

```powershell
cd voice-router-frontend
node server.mjs
```

Откройте http://127.0.0.1:8787. Остановка: Ctrl+C. Сервер слушает только локальный интерфейс.

## Три режима

| Режим | Как включить | Что действительно работает |
|---|---|---|
| Демо | Без ключа, кнопки готовых реплик | Заранее подготовленные ru/kk/mixed/clarify, trace и синтетические метрики |
| Проверка OpenAI | Новый ключ в серверном .env, поле текстового ввода | Ответ Responses API; **не** production-маршрутизация |
| Внешний Gateway | ?gateway=ws://localhost:8000/ws | WebSocket, текст, PCM16 mono 16 kHz, события роутера и публикации каталога |

В режиме демо микрофон не захватывается. Кнопки реплик не вызывают LLM. Произвольный текст без Gateway отправляется локальному API-proxy. Подключайте только доверенный Gateway: ему передаются текст, аудио и изменения каталога.

## Проверка за пять минут

1. Выберите первую демо-реплику: основной сценарий и дополнительное намерение.
2. Откройте трассировку: JSON, причина, альтернативы, последовательный водопад этапов. Это длительности, а не реальные перекрывающиеся timestamp spans.
3. Проверьте казахскую, смешанную и неоднозначную реплики. Для clarify scenario_id = null.
4. В супервизоре экспортируйте CSV текущей истории. Синтетические записи отмечены demo; верхние KPI — демонстрационные, не результаты eval.
5. В каталоге создайте сценарий, сохраните, перезагрузите страницу. Данные сохраняются в localStorage. Публикация в Gateway считается подтверждённой только после catalog_updated.
6. На узком экране используйте нижнюю навигацию.

## Тесты

```powershell
node --check app.js
node --check gateway.js
node --check server.mjs
node --test
```

Тесты запускают локальные HTTP-серверы и подменяют внешние ответы. Ключ и платные запросы не нужны. Проверяются .env, REST-формат ответа, закрытые файлы, валидация, ошибки API и граница WebSocket.

## Ограничения

Отдельный локальный backend реализует Gateway, серверный каталог, traces, очередь карточек и адаптеры OpenAI STT/LLM/TTS. Реальные вызовы новым ключом ещё не проверены. Production-развёртывание, eval и перевод звонка реальному оператору не реализованы. Изолированный server.mjs этого frontend остаётся только smoke-test proxy.

WebSocket рассчитан на последовательные повороты: transcript → route_decision → response_text → trace. Корреляцию параллельных запросов и reconnect/replay нужно согласовать с backend. Клиентский VAD — простой порог RMS, не production endpointing; при перегрузке аудиоканала звонок останавливается.

Без Gateway каталог хранится в localStorage и удаление локальное. С новым backend удаление выполняется на сервере после подтверждения; переименование ID при соединении запрещено. Другие открытые вкладки обновляют каталог после перезагрузки. Не вводите реальные клиентские/платёжные данные в демонстрацию.

Не публикуйте server.mjs в интернете: здесь нет пользовательской авторизации, долговременных квот или production-защиты.
