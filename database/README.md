# Работа с базой данных Voice Router

## Текущее состояние

В репозитории пока нет backend, подключения к СУБД, схемы и миграций. Frontend в demo mode хранит каталог сценариев и новые диалоги в `localStorage`; данные из `frontend/src/api/mockApi.ts` — примеры, а не записи реальной базы. Этот документ задаёт минимальную модель и порядок подключения базы, не привязывая команду к СУБД до выбора backend-стека.

## Что нужно хранить

| Сущность | Минимальные поля | Назначение |
| --- | --- | --- |
| `scenarios` | `id` (уникальный), `name`, `description`, `boundaries`, `examples_ru`, `examples_kk`, `created_at`, `updated_at` | Каталог маршрутов. |
| `calls` | `id`, `started_at`, `ended_at`, `status` | Сессия звонка. |
| `turns` | `id`, `call_id`, `created_at`, `text`, `lang`, `reply_text`, `tts_url` | Реплика клиента и ответ помощника. |
| `route_decisions` | `turn_id`, `scenario_id` (может быть `NULL`), `decision`, `confidence` (может быть `NULL`), `path`, `reason`, `topic_switch`, `additional_intents`, `alternatives` | Объяснимое решение роутера. |
| `trace_timings` | `turn_id`, `endpoint_ms`, `stt_ms`, `route_ms`, `exec_ms`, `first_audio_ms`, `playback_ms`, `total_ms` | Задержки этапов для waterfall. |

`turns.call_id` ссылается на `calls.id`; `route_decisions.turn_id` и `trace_timings.turn_id` — на `turns.id`. `route_decisions.scenario_id` ссылается на `scenarios.id`, когда сценарий выбран. Дополнительные намерения и альтернативы можно хранить как JSON-массивы по типу `RouteDecision` из `frontend/src/types.ts`.

Языки: `ru`, `kk`, `mixed`. Решения: `route`, `continue`, `clarify`, `handoff`, `out_of_scope`. Путь: `llm` или `fast`. Уверенность, если известна, находится в диапазоне 0–1.

**Отсутствующее измерение храните как `NULL`, а не `0`.** Тогда интерфейс покажет «нет данных», а агрегаты не будут искажены. Демо-задержки из mock нельзя включать в реальные p50/p95 и eval.

## Порядок подключения

1. Команда backend выбирает СУБД и фиксирует её в этом файле. До этого здесь нет команды, которая действительно поднимает базу.
2. Добавьте в backend `.env.example` переменную `DATABASE_URL` с локальным примером без пароля. Реальные учётные данные держите только в локальном `.env` или секретах окружения.
3. Создайте версионированную начальную миграцию для таблиц выше, внешних ключей и индексов `turns(call_id, created_at)`, `route_decisions(scenario_id)`.
4. Добавьте seed каталога с ID `payment_not_confirmed`, `change_delivery_address`, `refund_request` либо замените их согласованными ID. Seed должен быть повторяемым и не дублировать записи.
5. Реализуйте сохранение реплики, решения и трассировки как одну согласованную операцию. Ответ API отдавайте только после успешного сохранения.
6. Зафиксируйте реальные команды запуска базы, применения/отката миграций и seed в разделе ниже. После этого проверьте чтение каталога и диалогов через API.

## Контракт с frontend

Frontend переключается через `VITE_DEMO_MODE=false`, `VITE_API_URL` и `VITE_WS_URL`. Текущий `frontend/src/api/realApi.ts` содержит **предварительные** пути `GET /scenarios`, `PUT /scenarios/:id`, `GET /dialogs`, `GET /dialogs/:id`, `POST /calls`, `POST /calls/:id/turns` и `POST /calls/:id/end`. Backend-команда должна согласовать фактические пути, JSON-поля и WebSocket-события; после этого обновить адаптер. Страницы используют общий тип `VoiceRouterApi` и не должны читать базу напрямую.

Для списка диалогов отдавайте язык, выбранный сценарий, решение, статус и `total`; для детальной трассировки — также `reason`, альтернативы, дополнительные намерения и длительность каждого этапа. Сортировка последних диалогов — по `created_at` от новых к старым.

## Проверка после внедрения

- Миграция применяется на пустой базе и повторный запуск не создаёт дубликаты.
- Сценарий с существующим `id` нельзя создать повторно; изменение сценария сохраняется после перезапуска backend.
- Реплика с двумя намерениями сохраняет основной маршрут и очередь дополнительного намерения.
- Для отсутствующего тайминга API возвращает `null` или не передаёт поле, но не подставляет `0`.
- Диалог из списка супервизора открывает именно свою трассировку.
- Реальные метрики accuracy, p50/p95, clarify и handoff появляются только после запуска eval на размеченных данных.
